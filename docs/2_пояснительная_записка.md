## 1. Введение

### 1.1. Актуальность

Dota 2 — одна из самых популярных киберспортивных дисциплин в мире с более чем 700 000 активных игроков ежедневно. Большинство игроков стремятся улучшить свои навыки, но не имеют доступа к квалифицированному коучингу. Существующие платформы для поиска тренеров не специализируются на Dota 2 и не предоставляют интеграции с игровыми API.

**DotaTrener** решает эту проблему, предоставляя:
- Автоматизированный подбор тренеров на основе игровой статистики;
- Интеграцию со Steam API и Stratz API для получения актуальных данных о матчах;
- Внутренний мессенджер для общения между игроками и тренерами;
- Удобный инструмент для тренеров по продвижению своих услуг.

### 1.2. Цель проекта

Разработать кроссплатформенное мобильное приложение (Web + Android) для поиска и взаимодействия с тренерами по Dota 2, обеспечивающее:

1. Автоматическую синхронизацию статистики матчей через Steam API;
2. Каталог тренеров с фильтрацией по рейтингу, цене и специализации;
3. Внутренний мессенджер для общения;
4. Управление услугами и видео-материалами для тренеров.

### 1.3. Методы исследования

- Анализ существующих платформ коучинга (eGaming.coach, GamerSensei, Fiverr);
- Изучение API Steam, Stratz, OpenDota;
- Проектирование архитектуры на основе анализа требований;
- Итеративная разработка с использованием Agile-методологии.

## 2. Назначение и область применения программы

### 2.1. Назначение

**DotaTrener** — это программа для автоматизации процесса поиска и взаимодействия с тренерами по Dota 2. Программа предназначена для:

- **Игроков** — поиска тренеров, просмотра их услуг, общения через мессенджер;
- **Тренеров** — продвижения услуг, управления расписанием, общения с клиентами;
- **Администраторов** — модерации заявок тренеров.

### 2.2. Область применения

Программа используется в сфере киберспортивного коучинга и предназначена для:

- Индивидуального коучинга игроков Dota 2;
- Продажи видео-обзоров и разборов матчей;
- Организации групповых занятий по Dota 2.

### 2.3. Различные виды использования

| Вид использования | Описание |
|-------------------|----------|
| Поиск тренера | Игрок просматривает каталог тренеров, фильтрует по рейтингу, цене, специализации |
| Запись на услугу | Игрок выбирает услугу тренера и начинает диалог через мессенджер |
| Разбор матча | Тренер анализирует матч игрока, даёт рекомендации |
| Публикация видео | Тренер загружает видео-обзоры для продажи |
| Модерация | Администратор рассматривает заявки на становление тренером |

## 3. Описание алгоритмов программы

### 3.1. Алгоритм авторизации через Steam

```
1. Пользователь нажимает "Войти через Steam"
2. Клиент перенаправляется на URL Steam OpenID:
   http://83.222.16.188/api/auth/steam/login/
3. Steam перенаправляет пользователя обратно с параметрами:
   ?openid.identity=<steam_id>&token=<jwt_token>
4. Сервер создаёт/обновляет профиль игрока:
   - Получение данных о MMR и ранге через Stratz API
   - Сохранение steam_account_id и steam_id_64
5. Клиент сохраняет токен в localStorage/SecureStore
6. Пользователь перенаправляется на главный экран
```

### 3.2. Алгоритм загрузки матчей

```
1. Клиент отправляет GET /api/coaching/my-matches/
2. Сервер проверяет наличие Stratz токена у пользователя
3. Сервер отправляет запрос к Stratz GraphQL API:
   query { player(steamAccountId: <id>) { matches(limit: 20) { ... } } }
4. Сервер парсит ответ и формирует список матчей:
   - match_id, hero, result, side, duration, kda, gpm, xpm
5. Сервер возвращает JSON клиенту
6. Клиент отображает список с цветовой индикацией (победа/поражение)
```

### 3.3. Алгоритм отправки сообщения

```
1. Пользователь вводит текст и нажимает "Отправить"
2. Клиент отправляет POST /api/coaching/conversations/{id}/
   Body: { "text": "Текст сообщения" }
3. Сервер проверяет авторизацию и создает объект Message:
   - conversation_id = conversation.id
   - sender_id = request.user.id
   - text = request.data["text"]
4. Сервер обновляет updated_at у Conversation
5. Сервер возвращает созданный объект Message
6. Клиент добавляет сообщение в список
```

### 3.4. Алгоритм создания беседы

```
1. Игрок нажимает "Связаться" на услуге тренера
2. Клиент отправляет POST /api/coaching/conversations/
   Body: { "coach_id": id, "service_id": id, "message": "..." }
3. Сервер проверяет:
   - Существует ли уже беседа между этими пользователями
   - Если нет — создаёт новую Conversation
   - Создаёт первое Message с текстом
4. Сервер возвращает ID беседы
5. Клиент перенаправляется на экран чата
```

## 4. Описание структуры программы

### 4.1. Архитектура приложения

Приложение построено по архитектуре **Client-Server**:

```
┌─────────────────────┐         ┌─────────────────────┐
│      КЛИЕНТ         │         │      СЕРВЕР         │
│  (React Native)     │◄───────►│   (Django REST)     │
│                     │  HTTP   │                     │
│  ┌───────────────┐  │  JSON   │  ┌───────────────┐  │
│  │  Expo Router   │  │         │  │  DRF Views    │  │
│  │  (навигация)   │  │         │  │  (API)        │  │
│  └───────────────┘  │         │  └───────────────┘  │
│  ┌───────────────┐  │         │  ┌───────────────┐  │
│  │  Axios         │  │         │  │  Models       │  │
│  │  (HTTP)        │  │         │  │  (ORM)        │  │
│  └───────────────┘  │         │  └───────────────┘  │
│  ┌───────────────┐  │         │  ┌───────────────┐  │
│  │  SecureStore   │  │         │  │  SQLite       │  │
│  │  (токены)      │  │         │  │  (БД)         │  │
│  └───────────────┘  │         │  └───────────────┘  │
└─────────────────────┘         └─────────────────────┘
                                         │
                                         ▼
                                ┌─────────────────────┐
                                │  STRATZ API         │
                                │  (Dota 2 данные)    │
                                └─────────────────────┘
```
